03抽象接口：46 个端口

实现关系由 types.Implements 判定，所以隐式满足（Go 没有 implements 关键字）也被算到。橙色标出的实现住在外壳里——那些就是控制反转真正落地的地方。

端口浏览器

值得注意的三个形状

tool.Tool — 唯一的高扇出接口

5 个方法、26 个实现、24 个包引用。"工具执行位置无关"就靠它：本地工具、MCP 转发工具、沙箱转发工具，在权限门、harm 判定、事件流面前完全同形。 桌面专属的 open_preview 与 ReadOffice 从外壳侧实现同一接口，经 Options.ExtraTools 注入——外壳扩展引擎能力却一行都不改引擎，这是这套边界最值钱的一处。

SubagentLimiter — 被 internal 逼出来的孪生接口

engine.SubagentLimiter 与 subagent.Limiter 方法集完全相同。后者在 internal/ 里，Options 语法上没法引用它，于是根包声明了一个同形的；扫描确认两者互相满足。这是 Go 的 internal 约束逼出来的形状，不是冗余。

mcp.Launcher / ToolRuntime — 有引用、无实现的预留端口

mcp.Launcher 被引用 8 次、工作区内 0 个实现；ToolRuntime 只有一个 localRuntime。 它们是留给服务端宿主的："MCP 进程起在哪""内置工具在哪执行"由宿主决定，而协议之上的握手、发现、重连留在引擎。本仓两个外壳都走默认本地路径，所以这两个端口现在是空的——空得有意为之。

04方法面与 Wails 边界

Wails 要求所有命令挂在同一个类型上，所以 desktop.App 必然是宽的——74 个导出方法。分工靠文件而不是包。

74 个命令，60 个在 Go 侧零引用

扫描出的最有意思的一条：App 的 74 个命令方法里，60 个的 Go 侧引用数是 0。它们不是死代码——它们全部经 Wails 的反射绑定被前端调用，编译器看不见这条边。

这正是 tools/protogen 必须存在的理由：internal/protocol.CommandKinds（23 query / 24 idempotent-set / 25 trigger）与 App 的导出方法互相交叉核对，方法漏登记、或登记了不存在的方法，都让生成失败，CI 用 --check 把关。 编译器管不到的那条边，交给代码生成器管。

05跨包引用强度

174 条边。数字是"该包引用对面包符号的次数"，可以当耦合强度读——也可以反着读：数字小的边，说明那层确实薄。

引用最重的边
  • server → protocol 130 次，host → protocol 130 次——两个数字几乎相等，说明服务端骨架确实只吃 wire 契约，没有从引擎里多拿东西。
  • desktop → host 只有 47 次，而 desktop → 引擎根包 有 142 次：桌面在会话生命周期上依赖 host，在配置与状态类型上依赖引擎根包。薄适配层的数字画像。
  • cmd/runcode-desktop → internal/desktop 只有 4 次——Wails 层真的只有 Bind 那几行。
  • desktop → internal/protocol 424 次 vs desktop → agentloop/protocol 74 次：桌面自己的 DTO 都在自己家，没有漏进引擎契约。

10扫描口径与已知盲区

  • 只覆盖静态结构。运行期通过反射（Wails 绑定）、wire 协议（前后端）、os/exec（MCP stdio、hooks）连起来的边，静态分析看不见——这些边分别由 protogen --check、deps_test.go、集成测试兜住。
  • 引用计数不含测试文件。_test.go 被排除，所以"零引用"不代表"零测试"。
  • 依赖解析用 export data，不是全源码类型检查。packages.NeedDeps 关掉了——开着会连 modernc.org/libc 一起从源码类型检查，慢到不可用。这不影响本仓与引擎符号的精度：初始包全部是源码级类型检查，与 gopls 的取舍相同。
  • sessions/backendtest 是测试工具包，虽然不是 _test.go 但只服务测试，计入了包数与行数。
  • 地图不含制图者。tools/sysmap 把自己排除在扫描之外，否则每次改这个工具本身，全表数字都会漂。tools/protogen 不排除——它是构建契约的一部分，CI 会跑它。
  • LSP 路径不可用。本次环境没有配置 Go 语言服务器，也没装 gopls，所以直接调用了 go/packages + go/types——与 gopls 底下同一套机制，只是省掉了 LSP 那层协议。
