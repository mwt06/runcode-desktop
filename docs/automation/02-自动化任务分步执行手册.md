# 智开自动化任务分步执行手册

> **For agentic workers：** 实施时使用 `subagent-driven-development` 或 `executing-plans`，按任务逐项执行并记录证据。本文目前为计划，所有 checkbox 保持未完成；用户本轮要求编写文档，没有授权本轮启动实现。

**Goal：** 基于 `feat/upgrade-1118` 实现本机自动化任务、可恢复的执行记录及会话展示，并在 Windows 关闭主窗后通过同品牌托盘继续运行。

**Architecture：** `internal/automation` 拥有时间计算、独立 SQLite 和调度状态；`internal/desktop` 适配现有会话、身份、权限和事件。React 展示后端快照，ExecutionCard／ToolDetail 复用现有实现，Wails 宿主负责托盘与真正退出。

**Tech Stack：** Go、现有 modernc SQLite、Wails v3 `v3.0.0-beta.9`（Windows）、React 18／TypeScript／Vitest；沿用当前依赖，不改 agentloop Core。

**Spec：** [01-自动化任务执行方案.md](01-自动化任务执行方案.md)，必须先完整阅读。本文接口细化不得改变方案的用户行为。

## Global Constraints

- 当前审查基线：`feat/upgrade-1118@59cb3eeb7d5da1262a1ba7dd9f908143d42436aa`；正式实施重新核实，不使用旧 inline-preview worktree 作为新基线。
- 只改外壳仓；`GOWORK=off`，不修改 `../agentloop`、固定引擎 tag、无关模块和已有未提交的品牌构建资产。
- 关闭主窗＝隐藏继续调度；托盘使用当前品牌图标；有 enabled 或 active 任务真正退出必须确认“退出后自动化任务将无法执行”。
- 主发布平台 Windows；其他平台不假装具有托盘，保持原关闭退出能力与编译边界。
- 七种时间模式，无“自定义”／cron；创建只保存、不立即运行；工作区选择不改变当前会话。
- 暂停停止未来调度，已运行一轮继续；恢复只计算未来；晚到容差 60 秒；active 最多 1；每任务 queued 最多 1；active 总期限 60 分钟。
- scope 按真实认证来源区分 Passport／ChatGPT OAuth／本机静态密钥；每次凭据解析检查绑定，不自动批准任何权限。
- context `{viewId,epoch}`、task revision、runRevision 分别解决身份代际、任务更新和运行事件乱序；三者不可互相替代。
- 中文注释只解释关键决策：时间锚点、取消语义、提交不确定窗口、锁顺序和身份边界；不为每行赋值写重复注释。
- 样式遵守仓库 `CLAUDE.md` 和 `frontend/src/ui/README.md`；只用 token，前端必须 typecheck＋lint＋Vitest＋build。
- 关键步骤独立 commit；先检查差异，显式 `git add <文件>`，不用 `git add -A`；测试失败不得写成已完成。

## Review Focus

1. **双账号与混合认证：** ChatGPT A→B，或已登录 Passport 但任务用静态 key，不能串账号或误取消无关任务；归步骤 4、5。
2. **提交与完成颠倒：** 极快 turn 先完成、receipt 晚回、落库失败／崩溃，不重复发、不把终态改回 running；归步骤 3、4、6。
3. **客户端隐藏与退出竞争：** 两个关闭入口、重复退出、确认期间任务到期、取消后继续，不能销毁主窗或提前清理；归步骤 10。
4. **长时间休眠和特殊日期：** 每分钟任务休眠半年、月31日、DST 重复／缺失小时、时钟回拨，不爆量补跑；归步骤 1、3。
5. **工作区与历史变化：** 选择取消、目录消失、历史同名会话跨目录、复用会话被改模型／删除，不能改投当前会话；归步骤 4、6、8。

## 步骤 3：Go 调度服务和非阻塞运行事实

**Files：** 新增 `internal/automation/service.go`、`runner.go`、`service_test.go`、测试用 `fake_clock_test.go`。

**Interfaces：** 消费步骤 1～2，产出：

```go
type Submission struct { SessionID, QuestionID string }
type Runner interface {
    Start(ctx context.Context, task Task, run Run) (Submission, error)
    Cancel(ctx context.Context, run Run) error
}
func NewService(store *Store, runner Runner, clock Clock) *Service
func (s *Service) Start(ctx context.Context) error
func (s *Service) Observe(f Fact) // 快速记录终态，不阻塞 host Emit

func (s *Service) ExitSummary(ctx context.Context) (ExitSummary, error)
```

`Fact` 含 RunID、SessionID、LeaseGeneration、终态或等待状态、时间和安全摘要。`ExitSummary` 含 EnabledCount／UnfinishedCount（含queued，产品全量，不只可见 owners），与单active执行槽区分。release 幂等，只解除自己的 hold，不能清掉存储失败／系统退出的 hold。Service 还提供任务增改后唤醒和状态订阅 callback，由构造 options 注入，不能依赖 desktop。

## 异常、回退与继续规则

- 每次停下先记录最后已验证commit和未完成checkbox。失败时只修当前问题并重跑相应检查，不重做已通过且未受影响的全部步骤。
- DB迁移失败保留原库；存储异常禁止新派发；不删除用户任务以换“启动成功”。提交可能已接受时记待确认，不自动再发。
- 回退代码前保存数据库备份，不自动降级schema。暂停全部任务是用户可见的停止方式；测试中需要彻底停调度可通过服务测试依赖／退出进程，不能只卸载页面。
- Windows托盘不可达或退出竞态未过，步骤10、12不得勾选完成，也不能以保留隐形进程交付。其他平台尚未真机测的部分明确列限制。
- 所有commit显式暂存该步文件，检查 `git diff --cached --stat` 与 `git diff --cached` 后提交；构建资产、`.build-logs`、用户自己的工作不在本功能commit里。
