# 国家开放大学会议纪要格式

按学校模板校验会议纪要的排版与内容完整性，并一键改写。基准是
`assets/国家开放大学会议纪要模板.docx`，所有格式数值从它的 `word/document.xml`
提取核对，不采信模板正文里的文字标注。

## 什么时候用

- 「帮我看看这份会议纪要格式对不对」
- 「按国开的要求把这份纪要排一下」
- 「这份纪要缺什么」
- 「把这个 md 生成会议纪要」

输入是 `.docx` 走校验+改写；`.md` / `.txt` 走直接生成。`.doc` 需先转 `.docx`。

## 四步流程

### 第 1 步：校验，拿到问题清单

```bash
python scripts/check_format.py "纪要.docx" --json
```

JSON 里 `findings` 是逐条问题，`need_fill` 是**缺内容**的键，
`need_fill_labels` 给出对应中文名。人读的报告去掉 `--json`。

先把报告用自己的话讲给用户：多少项必改、多少项建议、哪几项脚本改不了。
不要直接把 JSON 贴给用户。

### 第 2 步：问用户要缺的内容

**这一步不能跳。** 脚本绝不自行编写纪要内容 —— 时间、地点、人名、议题、
帽子段都得用户给。按 `need_fill` 逐项问，一次问清，别一项一条消息。

**友好的提供给用户两种选择：**
1. **提供信息后再生成**：用户补齐缺项，拿到完整规范的纪要。
2. **先生成纪要，后续再优化**：用已有内容生成一版（缺项写 `【待补充：X】` 占位），
   告知用户"先用现有信息出一版，后续补充信息后我再帮你优化"。

问完写成 `fill.json`：

```json
{
  "meeting_name": "\"一平台\"项目",
  "title": "关于一平台二期建设推进的会议纪要",
  "time": "2026年8月6日（周四）下午14:00",
  "place": "五棵松A901会议室",
  "host": "张明",
  "attendees": "",
  "recorder": "杨亚菲",
  "topic": "一平台二期建设方案与排期确认",
  "lead": "根据《…》的工作部署，X部与Y部就…进行沟通，明确工作安排如下："
}
```

`meeting_name` 是红头第二行的会议名，脚本自动补「会议纪要」四字。
用户不想补某项时留空，脚本会写 `【待补充：X】` 占位并在摘要里列出 ——
这是有意的，让用户发文前一眼看到还差什么。

### 第 3 步：确认后改写

改写会生成新文件，问一句用户确认再动手。

```bash
python scripts/apply_format.py "纪要.docx" --fill fill.json
```

默认输出 `<原名>_国开会议纪要格式.docx`，**不覆盖原文件**（同路径会直接报错）。
`--output` 指定别的路径，`--dry-run` 只识别不写。

### 第 4 步：复校 + 如实交代

```bash
python scripts/check_format.py "纪要_国开会议纪要格式.docx"
```

报告给用户时，如实交代还剩什么。目前脚本唯一改不了的是：

- **文末照片**：模板要求纪要末尾附一张会议现场照片，脚本无法生成图片。
  线上会可以截一张参会画面。

红线脚本会自己补（红头末行的 3 磅红色下边框，与模板等宽），不用麻烦用户。
线画错位置（比如画到标题下面）也会自己纠正 —— 校验规则 B13。

已有的照片脚本会重排成 auto 行距，不会再被裁掉 —— 校验规则 H2。

## 正文核心结构

纪要正文（帽子段之后）分两段：

| 一级标题 | 内容 |
|---|---|
| **一、会议要点** | 每个要点用二级标题 `（一）（二）…` 编号。每个要点下简述讨论主题及达成的结论，**结论部分加粗**。不记录"谁说了什么"等细节讨论过程。 |
| **二、下一步工作计划** | 直接用 `1. 2. 3. …` 编号，逐条列出待办事项。不需要加（一）（二）等二级标题，1.2.3. 本身就是正常编号。责任人与截止时间为可选项。 |

文末自动插入居中占位段落 `【请在此处插入会议照片】`。

## md/txt 直接生成

```bash
python scripts/build_from_text.py 纪要.md --fill fill.json -o 输出.docx
```

拿模板当骨架（保留 sectPr、样式定义、红头与红线），按 md 结构插段落：

| md 写法 | 产出 |
|---|---|
| `# 标题` | 纪要标题（居中，方正小标宋简体 18pt） |
| `## 会议要点` | `一、会议要点`（自动编号，黑体加粗） |
| `### 第三方测试` | `（一）第三方测试`（楷体_GB2312 加粗） |
| `#### 补充材料` | `1. 补充材料`（仿宋_GB2312） |
| `时间：…` 等顶部标签行 | 信息栏对应项 |
| `信息化部：张三、李四` | 出席人员下方的部门行 |
| 其余段落 | 正文，第一段作帽子段 |

编号由脚本生成，md 里不用自己写「一、」。信息栏 md 里写了的优先，
缺的从 `--fill` 取。

md 里自己手写了「（一）」「1.」这类编号时，脚本按对应级别排，不当普通正文 ——
两边判定走同一个 `heading_role()`，否则产出会自己报 F1。
md 正文中的 **加粗** 标记会自动识别并生成加粗 run，用于突出结论要点。不成对的 ** 原样保留。

## 格式要点

| 元素 | 中文字体 | 字号 | 其他 |
|---|---|---|---|
| 页面 | — | — | A4，四边页边距 2.54cm |
| 红头 2 行 | 黑体 | 26pt | 加粗、红色 FF0000、居中、行距固定 30 磅 |
| 标题 | 方正小标宋简体 | 18pt | 居中、不加粗 |
| 信息栏标签 | 黑体 | 16pt | 补齐到 4 个汉字宽，如「时」+8空格+「间」 |
| 信息栏值 | 仿宋_GB2312 | 16pt | 同段落内跟在标签后 |
| 正文 | 仿宋_GB2312 | 16pt | 首行缩进 2 字符、两端对齐 |
| `一、` | 黑体 | 16pt | 加粗、同正文缩进 |
| `（一）` | 楷体_GB2312 | 16pt | 加粗、同上 |
| `1.` 及以下 | 仿宋_GB2312 | 16pt | 同上 |
| 西文数字 | Times New Roman | 随中文 | 全文统一 |
| 红线 | — | — | 红头末行下边框，3 磅 FF0000，脚本自动补 |
| 文末照片段 | — | — | 居中、不缩进、**行距 auto** |

行距：红头 30 磅，其余全部固定 28 磅 —— **只有照片段例外**。
固定行距对 inline 图片是硬裁剪，11.92cm 的照片按 28 磅排只剩 0.99cm，
裁掉 92%，只露出顶上一条。照片段必须用 auto 让 Word 按图片高度撑开。

**标题与说明合排**（`（一）登录认证演示。演示了……`）：标题部分用该级标题
字体并**加粗**，其后说明保持仿宋_GB2312。整段刷标题字体会让一大段说明变楷体，
不是模板的意思。脚本自动识别并拆分。

**加粗规则区分**：
- **会议要点**下的三级标题 `1. 2. 3.…`（独占一行时）需要**加粗**，与二级标题
  `（一）（二）` 保持一致的加粗风格。
- **下一步工作计划**下的 `1. 2. 3.…` **一定不要加粗**，保持仿宋_GB2312 正文样式，
  与会议要点下的同级编号明确区分。
信息栏七项顺序固定：时间、地点、主持人、出席人员、记录人、会议议题、会议内容。
「会议内容：」之后必须先有一段无编号的帽子段交代背景，不能直接进「一、」。

完整规格见 `references/format-spec.md`，规则 ID 与能否自动修的对照表见
`references/check-rules.md`。

## 三条不要

1. **不要替用户编内容。** 缺时间就问时间，缺帽子段就问帽子段。脚本设计上
   也不会编 —— 没给的写 `【待补充：X】`。编出来的会议信息是要进档案的假记录。
2. **不要覆盖原文件。** 一律写新文件。用户没明确要求前，别删原件。
3. **不要谎报修好了。** 文末照片脚本改不了，复校后如实说。
   `方正小标宋简体` 本机常缺，Word 预览会替换显示，但**文件里存的字体名是对的** ——
   跟用户说清这点，别当成 bug 去改。

## 脚本一览

| 脚本 | 作用 |
|---|---|
| `check_format.py` | 校验，出文本报告或 `--json`；有必改项时退出码 1 |
| `apply_format.py` | docx → 合规 docx（新文件） |
| `build_from_text.py` | md/txt → 合规 docx |
| `mj_docx.py` / `mj_spec.py` | 底层与规格，不单独调用 |

纯标准库（`zipfile` + `xml.etree`），无第三方依赖。改写走 unzip → 改
`document.xml` → repack，图片、表格、批注等部件字节级保留，产出后自检三项：
`testzip()`、XML 解析、**命名空间前缀声明齐全**。第三项不能省 —— 前缀漏声明时
前两项全过，Word 却拒绝打开报「文件可能已经损坏」，详见
`references/format-spec.md` 的「回写的命名空间陷阱」。
