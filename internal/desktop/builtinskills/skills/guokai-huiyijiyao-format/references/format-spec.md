# 国家开放大学会议纪要格式规格

数值全部从 `assets/国家开放大学会议纪要模板.docx` 的 `word/document.xml`
逐项提取核对。**以 XML 为准，不采信模板正文里的文字标注** —— 见文末「模板的两处自相矛盾」。

单位：twip（1 英寸 = 1440，1cm = 1440/2.54 ≈ 566.93）；字号 `w:sz` 用半磅
（三号 16pt → 32）；固定行距 `w:line` 用 twips（28 磅 → 560，`lineRule="exact"`）。

## 页面

| 项 | 值 | XML |
|---|---|---|
| 纸张 | A4 | `w:pgSz w:w="11906" w:h="16838"` |
| 上下左右页边距 | 2.54cm = 1440 twips | `w:pgMar top/bottom/left/right="1440"` |
| 页眉页脚 | 708 twips | `w:pgMar header/footer="708"` |
| 装订线 | 0 | `w:gutter="0"` |

校验容差：纸张 ±20 twips（不同工具对 A4 取整不同，11900/11906 都算过），
页边距 ±0.05cm。

## 各角色

| 角色 | 中文字体 `w:eastAsia` | `w:sz` | 加粗 | 颜色 | 对齐 | 行距 | 首行缩进 |
|---|---|---|---|---|---|---|---|
| 红头 2 行 | 黑体 | 52（26pt） | 是 | FF0000 | center | exact 600（30 磅） | 无 |
| 标题 | 方正小标宋简体 | 36（18pt） | 否 | 自动 | center | exact 560 | 无 |
| 信息栏标签 | 黑体 | 32（16pt） | 否 | 自动 | left | exact 560 | 无 |
| 信息栏值 | 仿宋_GB2312 | 32 | 否 | 自动 | left | exact 560 | 无 |
| 部门行 | 仿宋_GB2312 | 32 | 否 | 自动 | left | exact 560 | 无 |
| 帽子段 | 仿宋_GB2312 | 32 | 否 | 自动 | both | exact 560 | `firstLineChars=200` |
| 一级 `一、` | 黑体 | 32 | 是 | 自动 | both | exact 560 | `firstLineChars=200` |
| 二级 `（一）` | 楷体_GB2312 | 32 | 是 | 自动 | both | exact 560 | `firstLineChars=200` |
| 三级 `1.` | 仿宋_GB2312 | 32 | 否 | 自动 | both | exact 560 | `firstLineChars=200` |
| 四级 `（1）` | 仿宋_GB2312 | 32 | 否 | 自动 | both | exact 560 | `firstLineChars=200` |
| 正文 | 仿宋_GB2312 | 32 | 否 | 自动 | both | exact 560 | `firstLineChars=200` |
| **照片段** | 仿宋_GB2312 | 32 | 否 | 自动 | center | **auto 240** | **无** |

照片段是**唯一不用固定行距**的段落，理由见下文「文末照片」。

红头段后距 12pt（`w:after="240"`）。其余段落 before/after 均为 0。

西文与数字全文统一 `w:ascii` / `w:hAnsi` / `w:cs` = `Times New Roman`，
`w:hint="eastAsia"`。

写入首行缩进时同时给 `firstLineChars=200` 与 `firstLine`（= 缩进字符数/100 ×
半磅字号 × 10 = 640 twips @16pt）。`firstLineChars` 是权威值，`firstLine`
给不认字符缩进的旧版本兜底。

## 红头

两行，居中：

```
国家开放大学
"一平台"项目会议纪要
```

第一行固定 `国家开放大学`。第二行是「会议名 + 会议纪要」，项目名可变，
尾部固定「会议纪要」四字。

### 识别必须锚定第一行

红头判定的**唯一入口是「第一个非空段等于 `国家开放大学`」**。不成立就判
**全篇无红头**，那些段落交给标题规则。

不能拿「或以『会议纪要』结尾」当或条件 —— 纪要标题本身几乎总以「会议纪要」
结尾（`国开AI基座项目周例会会议纪要`），那样会把没有红头的文件的**标题**
误认成红头。实测 36 份真实纪要：

| 判定 | 份数 |
|---|---|
| 或条件判对 | 6 |
| **或条件判错**（标题被认成红头） | **30** |

误判的连带后果是红线锚错段落，画到标题下面。识别时同时**最多取 2 行**，
防止第二行也把标题吞进来。

### 红色横线

红头下方有一条红线，公文惯例，必备。**两种实现都合规，校验都认。**

**模板的做法** —— 锚定在红头第二段的浮动 line 形状：

```xml
<a:prstGeom prst="line"/>
<a:ln w="38100"><a:solidFill><a:srgbClr val="FF0000"/></a:solidFill></a:ln>
```

宽 38100 EMU = 3pt，长 5734050 EMU。整个形状连 VML 兜底共 5498 字符，
但**不引用任何 media 部件**（无 `r:embed` / `r:id`），所以它是纯 XML 的。

**脚本补线的做法** —— 红头末行的段落下边框：

```xml
<w:pBdr><w:bottom w:val="single" w:sz="24" w:space="8" w:color="FF0000"/></w:pBdr>
```

`w:sz` 单位 1/8 磅，24 = 3 磅，与模板同宽。长度上：文本栏宽 =
21cm − 2.54×2 = **15.92cm**，模板线长 5734050 EMU = **15.93cm**，差 0.01cm，
视觉等价。

选下边框而不是克隆浮动形状，理由是可靠性：下边框只要一行 XML，不需要
drawing 部件、不需要 rels 与 `[Content_Types].xml` 条目，也不会像浮动图形
那样在用户后续编辑时被挪位或误删。**不需要用户手动插入，也不需要生成图片。**

校验时 `find_redline()` 两种都识别，返回统一折算成 EMU 的线宽（边框
`w:sz` × 12700 ÷ 8），容差 ±0.5pt。

改写红头文字时必须只删有文字的 run、保留带图形的 run，否则模板自带的
浮动红线会跟着丢。

## 信息栏

七项，顺序固定，缺任一项都是必改：

| key | 标签 | 补齐后 | 内容示例 |
|---|---|---|---|
| `time` | 时间 | `时` + 8空格 + `间` | 2026年8月6日（周四）下午14:00 |
| `place` | 地点 | `地` + 8空格 + `点` | 五棵松A901会议室 |
| `host` | 主持人 | `主` + 2空格 + `持` + 2空格 + `人` | 任冉 |
| `attendees` | 出席人员 | 原样（已 4 字） | 值可空，下方按部门分行 |
| `recorder` | 记录人 | `记` + 2空格 + `录` + 2空格 + `人` | 杨亚菲 |
| `topic` | 会议议题 | 原样 | 一句话议题 |
| `content` | 会议内容 | 原样 | 固定为「会议内容：」，其后接帽子段 |

标签后跟**全角冒号**。半角冒号报建议级。

### 标签补齐规则

全部补到 **4 个汉字宽**，用 ASCII 空格填在字与字之间，均匀分配。
空格按 1/4 汉字宽计：

```
2 字：4 - 2 = 2 汉字宽 = 8 个空格，1 个间隙 → 「时」+8空格+「间」
3 字：4 - 3 = 1 汉字宽 = 4 个空格，2 个间隙 → 「主」+2空格+「持」+2空格+「人」
4 字：不补
```

这条规则逐项核对，能字节级复现模板全部 7 个标签。

### 同段落双字体

信息栏一段内标签黑体、值仿宋_GB2312，是两个 run。整段刷同一字体是错的。
段落标记的 `rPr` 随值的字体，这样用户接着打字延续正文体例。

### 部门行

「出席人员：」下方按部门分行，如 `信息化部：任冉、杨亚菲`。这些是**值行不是标签行**，
整行仿宋_GB2312、不缩进。识别正则容忍标签内的填充空格（模板里有
`教  务  部：赵东伟` 这种写法）。

## 正文结构

「会议内容：」之后必须先有一段**无编号的帽子段**，交代会议背景与总体安排，
不能直接进「一、」。模板原话：「会议要加帽子，简要介绍情况」。

帽子段短于 20 字报建议级（大概率没写全）。

### 内容结构

纪要正文（帽子段之后）分两段：

| 一级标题 | 内容 |
|---|---|
| **一、会议要点** | 每个要点用二级标题 `（一）（二）…` 编号。每个要点下简述讨论主题及达成的结论，结论部分加粗。不记录"谁说了什么"等细节讨论过程。 |
| **二、下一步工作计划** | 用三级标题 `1. 2. 3. …` 有序编号，逐条列出待办事项。责任人与截止时间为可选项。 |

文末自动插入居中占位段落 `【请在此处插入会议照片】`。

标题层级：`一、` → `（一）` → `1.` → `（1）`。跳级报建议级，包括
**首个标题不是一级**的情况（正文直接从 `1.` 开始也算）。

### 标题与说明合排

实际纪要里常见这种写法 —— 标题和说明写在同一段：

```
（一）登录认证演示。演示了融合门户登录、AI基座登录、OA系统登录三种登录方式，
验证了客户端与校内现有身份认证体系的对接能力。
```

这时**整段刷标题字体是错的** —— 一大段说明文字变楷体，观感不对。正确排法是
一段内两种 run：

| 部分 | 字体 | 加粗 |
|---|---|---|
| `（一）登录认证演示。` | 该级标题字体（二级 = 楷体_GB2312） | **是** |
| 其后的说明文字 | 仿宋_GB2312 | 否 |

加粗是为了在字体差异之外再给一重区分，合排时标题才拎得出来。
纯标题独占一行时也加粗（一级黑体、二级楷体均加粗）。

判定靠 `split_inline_heading()`：编号 + 短语 + 首个句号/分号/冒号为标题部分，
其后有内容才算合排。标题部分超过 30 字就不认（那更可能是一整段正文）。
校验器同样要认这个结构 —— 否则会拿最长的说明 run 当代表，把正确排版
误报成字体不符（F1）。

## 段落角色识别

保守原则：**认不出就归 body，绝不删字或重排。**

顺序：

1. 红头 —— 第一个非空段**必须等于**「国家开放大学」；成立时第二行以
   「会议纪要」结尾也算。不成立则判全篇无红头（见上文「识别必须锚定第一行」）
2. 信息栏 —— 文本以七项标签之一 + 冒号开头（容忍填充空格与半角冒号）
3. 部门行 —— 首个信息栏之后、末个信息栏之前，形如「XX：人名」且不是信息栏标签
4. 标题 —— 红头之后、第一个信息栏之前的非空段
5. 帽子段 —— 「会议内容：」之后第一个无编号段
6. 各级标题 —— 按 `（1）` → `（一）` → `一、` → `1.` 的顺序匹配（先长后短）
7. 照片段 —— 段落里有 `a:blip`（真图片引用）
8. 空段 —— 其余无文字段落

`（1）` 必须在 `一、` 之前判，否则 `（1）` 会被误判。
照片判定用 `a:blip` 而不是 `w:drawing`，否则红线会被当成照片。

## 文末照片

纪要末尾附一张会议现场照片。脚本不生成图片，但**必须正确排版已有的照片段**。

### 固定行距会把照片裁掉

实际纪要里的照片是 **inline 图**（`wp:inline`，随文字流），不是浮动图。
`lineRule="exact"` 对 inline 图是**硬裁剪** —— Word 不会为图片长高，
超出行高的部分直接不显示：

| | 值 |
|---|---|
| 照片高 | 11.92 cm |
| 固定行距 28 磅 | **0.99 cm** |
| 被裁掉 | 10.93 cm = **92%** |

结果就是只露出照片顶上窄窄一条。所以照片段**不能按正文排**，
行距要交给 Word 自适应：

```xml
<w:spacing w:line="240" w:lineRule="auto" w:before="0" w:after="0"/>
```

**依据不是推测**：实测 33 份带照片的真实纪要，照片段行距**全部是 `auto`**，
没有一份用 `exact`。模板自身没有照片段（唯一带 drawing 的是红头第一段
那条浮动红线），所以这条规格取自实际文件的一致做法。

### 首行缩进也要清

| | 值 |
|---|---|
| 文本栏宽（21 − 2.54×2） | 15.92 cm |
| 照片宽 | 15.89 cm |
| 首行缩进 2 字符（640 twips） | 1.13 cm |
| 缩进 + 照片 | 17.02 cm → **溢出 1.10 cm** |

照片本来就占满整栏，所以缩进归 0、居中对齐。

### 照片段怎么认

靠 `a:blip`（真图片引用），不是 `w:drawing` —— 红线那条浮动形状也是
`w:drawing`，用后者会把红线当成照片。实测 261 个照片段**没有一个带文字**，
所以照片段独占段落这个假设是成立的。

## 模板的两处自相矛盾

1. **「一级标题黑体小三」**：模板正文这么写，但 XML 里实际 `w:sz="32"`
   （三号 16pt），不是小三（15pt）。以 XML 为准 —— 那是模板真正编码的值。
2. **「最后附一张照片」**：这句话在，但 zip 内**没有 media 部件**，
   模板自己没有照片。校验只判断「文末有没有图片」，报建议级。
   照片段的行距规格因此取自 33 份实际纪要，不是取自模板。

## 回写的命名空间陷阱

`ElementTree` 只保留 `register_namespace()` 登记过的前缀，其余一律重写成
`ns0`/`ns1`/…。但根标签上的 `mc:Ignorable="w14 w15 wp14"` 里写的还是原名，
那几个前缀就此失去声明：

```xml
<!-- ET 直接 tostring 的产物：ns1 声明了，Ignorable 里点的 w14/w15/wp14 没有 -->
<w:document xmlns:ns1="…markup-compatibility/2006" xmlns:w="…"
            ns1:Ignorable="w14 w15 wp14">
```

**后果是 Word 拒绝打开、报「文件可能已经损坏」，而 XML 依然合法可解析** ——
`testzip()` 和 `ET.fromstring()` 都查不出来。实测本机 Word：
`Documents.Open()` 直接失败，加 `OpenAndRepair=True` 才打得开。

两道防线：

1. `NS_PREFIXES` 把标准前缀全登记上（`w r mc m wp a pic o v w10 w14 w15
   w16se w16cid wne wpc wpg wpi wps wp14 a14 wpsCustomData`）
2. `load_document()` 用字节切出**原始根起始标签**存下来，`serialize()` 回写时
   换回去，再按 URI 比对补上 ET 新增的声明（`merge_root_ns()`）。这一步保住
   表里没有的前缀，比如 WPS 的 `wpsCustomData`

`a` / `pic` 这类前缀常只在 drawing 子树上就地声明，ET 会把它们提到根上 ——
按 URI 比对就不会重复声明。

`validate_docx()` 因此有第三项检查 `check_namespaces()`：根标签是否声明了
所有被用到的前缀 + `Ignorable` 里点到的前缀。只查 zip 与 XML 解析漏过一次。

## 字体可用性

`方正小标宋简体` 多数机器没装（本机也没有），Word/WPS 预览标题时会替换显示。
**文件里存的字体名是正确的**，在装了该字体的机器上打开就正常。
仿宋_GB2312、楷体_GB2312、黑体 常见系统一般都有。
