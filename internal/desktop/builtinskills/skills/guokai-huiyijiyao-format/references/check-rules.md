- ✅ 直接改

## 容差

| 项 | 容差 | 为什么 |
|---|---|---|
| 字号 | 0 | 半磅整数比对，没有取整歧义 |
| 行距 | ±10 twips（0.5 磅） | 不同工具写 `line` 有细微差异 |
| 首行缩进 | ±10（0.1 字符） | 同上 |
| 页边距 | ±0.05cm | cm↔twips 换算取整 |
| 纸张 | ±20 twips | A4 有 11900/11906 两种常见写法 |
| 红线线宽 | ±6350 EMU（0.5 磅） | 同上 |

## 编排层要读的字段

`--json` 输出：

```json
{
  "counts": {"error": 3, "warn": 2, "info": 0},
  "has_error": true,
  "findings": [{"rule": "D1", "level": "error", "message": "…",
                "paragraph": null, "actual": null, "expected": "…",
                "fixable": true, "fill_key": "recorder"}],
  "need_fill": ["meeting_name", "recorder"],
  "need_fill_labels": {"meeting_name": "红头会议名称", "recorder": "记录人"}
}
```

`need_fill` + `need_fill_labels` 就是要问用户的清单，照 label 念即可。
`fixable: false` 的项在报告里必须点名 —— 那些是改写后仍然存在的问题。

## 一条判定口径

每段取**字数最多的 run** 作代表判字体字号。段落里混排（比如正文里夹了个
英文词单独设了字体）不会因少数字符报错，但 I1 会单独扫全部 run 的西文字体。
